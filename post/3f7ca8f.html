电脑配置双VPN

发表于2026-05-11|更新于2026-05-11|计算机网络网络配置
|字数总计:2.9k|阅读时长:12分钟|阅读量:

背景

在开发过程中，有时需要同时连接两个不同的VPN（例如：VPN A、VPN B）。但某些VPN连接后会篡改系统DNS或覆盖路由表，导致另一个VPN的内网资源无法访问。

具体现象：

  • VPN B（类似SDP类产品）连接后会强制修改Wi-Fi的DNS地址。
  • 单独连接任一VPN时，内网访问正常。
  • 同时连接两个VPN后，无论连接顺序如何，后连接的VPN所对应的内网资源完全无法访问。

解决思路

  1. 修复DNS
    连接完所有VPN后，将Wi-Fi接口的DNS手动设置为原有的运营商DNS或内网DNS，避免被单一VPN覆盖。
  2. 静态路由分流
    为两个VPN分别添加精确路由：
    • VPN A 的内网段（例如 192.168.56.0/24，192.168.57.0/24）强制走 VPN A 的虚拟网卡（utunX）
    • VPN B 的内网IP和段（例如 192.168.20.0/24 及特定主机IP）强制走 VPN B 的虚拟网卡（utunY）
    • 默认流量仍走物理Wi-Fi网关，保证公网访问正常。
  3. 域名硬解析（可选）
    对于必须通过域名访问的内网资源，可先ping或nslookup获得内网IP，补充到/etc/hosts中，避免DNS解析被错误流量路由。

自动修复脚本（macOS）

使用前提：

  • 已连接两个VPN。请根据实际VPN的虚拟网卡IP前缀修改脚本中的检测逻辑（见脚本开头处）。
  • 系统已安装nc（netcat）和route命令（macOS自带）。
  • 需要sudo权限执行路由和DNS修改。

脚本功能：

  • 自动识别VPN A网卡（例如IP段10.1.x.x）和VPN B网卡（例如IP段10.2.x.x）—— 请根据实际IP段修改脚本中的判断条件。
  • 重置Wi-Fi的DNS为指定服务器（可根据需要修改）。
  • 删除冲突的旧路由，添加精确分流路由。
  • 修正默认网关为Wi-Fi物理接口。
  • 执行连通性测试（公网、VPN A资源、VPN B资源及域名）。

bash

使用方法

  1. 将上述脚本保存为 fix_vpn_routes.sh。
  2. 根据你的实际环境修改脚本中的以下内容：
    • 第27–28行：VPN_A_IP_PREFIX 和 VPN_B_IP_PREFIX，设置为两个VPN虚拟网卡获取到的内网IP前缀（例如 10.1. 和 10.2.）。
    • 第76行：DNS服务器地址（networksetup -setdnsservers 部分）。
    • 第81–88行：路由条目（route delete/add 部分）中的内网段和特定主机IP。
    • 第129–134行：测试用的内网域名及对应的预期IP（可选，用于域名连通性检测）。
  3. 赋予执行权限：chmod +x fix_vpn_routes.sh。
  4. 确保已按顺序连接VPN（若顺序影响网卡IP分配，请保证连接后即可检测到对应IP前缀）。
  5. 执行脚本：./fix_vpn_routes.sh（需要输入sudo密码）。
  6. 观察输出，确认每一步均为绿色“通过”。

注意事项

  • 脚本中Wi-Fi接口名称默认为"Wi-Fi"，若系统使用其他名称（如"en0"），请修改networksetup -setdnsservers和网卡识别部分。
  • DNS服务器地址可根据实际网络环境修改。
  • 如果VPN的内网IP段发生变化，需同步更新脚本中的路由条目。
  • 该脚本仅作为示例框架，不同公司的内网环境请务必按需调整IP段、域名和虚拟网卡识别逻辑。

问题

Q：为什么脚本中需要设置VPN网卡的IP前缀？
A：因为不同VPN的虚拟网卡（utun）编号不固定，通过IP地址前缀可以稳定识别哪个网卡属于哪个VPN。你需要先用 ifconfig 查看两个VPN网卡的IP地址，找到它们各自的前两段（例如 10.1.x.x 和 10.2.x.x），然后填入脚本。

Q：执行后仍然无法访问某个内网域名？
A：请检查/etc/hosts中是否已添加该域名的内网IP，或者使用nslookup确认域名解析结果是否指向内网IP。某些VPN会强制劫持DNS，建议在脚本的DNS列表中加入内网DNS服务器。

Q：能否在Windows上使用？
A：本脚本专为macOS设计（依赖networksetup、route、ifconfig utun）。Windows可参考思路，使用route add配合netsh interface ip set dns实现。

Q：为什么必须先连接VPN A再连VPN B？
A：这取决于两个VPN的网卡IP分配顺序。脚本通过IP前缀识别，只要连接后两个虚拟网卡的IP前缀不同且稳定，连接顺序可以任意，但你需要在脚本中正确配置对应的前缀。如果顺序导致IP前缀发生变化，请调整连接顺序或修改脚本逻辑。
