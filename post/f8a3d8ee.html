js 精度丢失问题记录

发表于2026-06-05|更新于2026-06-05|技术前端js
|字数总计:1.6k|阅读时长:6分钟|阅读量:

本文用于记录在开发过程中遇到的一些问题

问题概述

问题现象

在前端页面调用接口时，发现多条不同数据的 id 字段显示为相同的值。

排查过程

  1. 初步怀疑：接口返回数据有问题
  2. 验证接口：使用 Apifox 直接调用接口，返回的 id 各不相同 ✅
  3. 检查浏览器：浏览器控制台”响应”标签显示的 id 也不相同 ✅
  4. 发现问题：浏览器控制台”预览”标签显示的 id 相同 ❌
  5. 定位原因：问题出在 axios 响应拦截器的数据解析环节

根本原因

JavaScript Number 类型精度限制导致 Long 类型数据解析时丢失精度。

问题分析

技术背景

  • 后端：Java Long 类型（64位整数）
  • 前端：JavaScript Number 类型（IEEE 754 双精度浮点数）
  • 限制：JavaScript 最大安全整数为 2^53 - 1 = 9007199254740991

数据流转过程

为什么浏览器”响应”和”预览”显示不同？

标签 显示内容 是否解析 结果
响应 HTTP 原始响应体（字符串） ❌ 未解析 ✅ 正确
预览 axios 解析后的对象 ✅ 已解析 ❌ 错误

解决方案

核心思路

在 axios 执行 JSON.parse() 之前拦截原始响应数据，将超过安全范围的数字转换为字符串，避免精度丢失。

处理逻辑

  1. 拦截时机：axios 的 transformResponse 配置项（在 JSON.parse 之前执行）
  2. 匹配规则：正则表达式 /([:\[]\s*)(-?\d{16,})(\s*[,}\]])/g
    • 查找 JSON 中 16 位及以上的数字
    • 支持负数
    • 支持对象值和数组元素
  3. 判断条件：数字长度 ≥ 16 且 > 9007199254740991
  4. 转换方式：给数字加双引号，变为字符串
  5. 解析数据：转换完成后调用 JSON.parse()

影响范围

受影响的字段类型

  • ✅ 订单号、流水号等 Long 类型 ID
  • ✅ 时间戳（13位毫秒时间戳不受影响）
  • ✅ 超大金额字段
  • ✅ 其他超过 9007199254740991 的数字

不受影响的情况

  • ❌ 15 位及以下的数字（在安全范围内）
  • ❌ 小数（不受此正则影响）
  • ❌ 已经是字符串的数字

验证方法

方法一：浏览器控制台

方法二：对比 Apifox

  1. 用 Apifox 调用接口，记录返回的 ID
  2. 用前端页面调用同一接口，打印 ID
  3. 对比两者是否一致

方法三：查看网络请求

  1. 打开浏览器开发者工具 → Network
  2. 找到对应的接口请求
  3. 对比”响应”和”预览”标签：
    • 响应：应该显示原始数字
    • 预览：应该显示字符串（带引号）
